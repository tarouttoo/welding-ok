# Словарь граф: контракт → форма ОК

Назначение: справочное соответствие «поле [`ok.json`](../contract/README.md) →
графа формы операционной карты» (форма по ГОСТ 3.1118-82, содержание граф по
ГОСТ 3.1404-86). Общее для агента и рендерера.

> **Граница (ADR 0001).** Нормативное отображение полей в графы и точная
> нумерация граф — предмет задачи рендерера; этот файл её не предрешает и
> номеров граф не фиксирует. Здесь закреплено соответствие **по содержанию** —
> чтобы агент знал, куда переносится каждое значение и как его формулировать.

> **Статус: черновик агента.** Соответствия граф и формулировки значений
> проверяет инженер вместе с рендерером (задача #4).

## Соответствие по содержанию

| Графа формы ОК (по содержанию) | Поле контракта | Как формулировать значение |
| ------------------------------ | -------------- | -------------------------- |
| Номер цеха, участка, рабочего места | — | Нет в контракте v1; проставляется при рендере/вручную ⚠. |
| Номер операции | `operations[].number` | Целое, по порядку выполнения. |
| Код и наименование операции | `product.process` + документ в целом | «Сварка ручная дуговая» (v1: процесс всегда `РД`). |
| Обозначение изделия | — | Нет в контракте v1 ⚠ (кандидат на расширение контракта — отдельная задача). |
| Наименование детали (изделия) | `product.name` | Как на чертеже изделия. |
| Марка материала (основной материал) | `product.material` | `ст3`, `09Г2С` — без склонения. |
| Сварочные материалы: марка, диаметр | `equipment.electrode_type`, `params.electrode_diameter_mm` | «Электроды УОНИ-13/55 Ø4»; диаметр — с запятой-дробью по ГОСТ, если не целое. |
| Код и наименование оборудования | `equipment` (частично) | v1: пост постоянного тока; электрод — сварочный материал, не оборудование ⚠ (распределение уточнить при разработке рендерера). |
| Положение сварки | `operations[].position` | Именованное положение: «нижнее», «вертикальное», «потолочное», «горизонтальное на вертикальной плоскости». |
| Род тока | `params.current_type` | «постоянный» (v1 знания переменный не выдают). |
| Полярность | `params.polarity` | «обратная» (v1 знания прямую не выдают); при `переменный` графа не заполняется — полярность не задаётся. |
| Сварочный ток | `params.current_a` | Число с «А», из диапазона режимной таблицы. |
| Число проходов | `params.pass_count` | Целое. |
| Содержание строки (переход) | `transitions[].description` | Текст перехода как есть; стилистика — [`assembly_transitions.md`](assembly_transitions.md). |
| Обозначение швов | `operations[].welds` | `Ш<n>` по нумерации чертежа; упоминаются в тексте переходов и на эскизе КЭ. |
| Ссылка на эскиз | `operations[].sketch_refs` | `КЭ<n>` — заглушка-ссылка на карту эскизов; сам эскиз выполняется вручную. |
| — (служебное) | `assumptions[]` | **В ОК не переносится**: поле черновика, разбирается при приёмке. |

## Соглашения

- Ключи контракта — латиница `snake_case`; в графы переносятся только русские
  значения (правило зафиксировано в
  [`../contract/README.md`](../contract/README.md)).
- Термины граф — по [`../GLOSSARY.md`](../GLOSSARY.md); ГОСТ терминология не
  переводится.
- Графы, у которых в колонке поля стоит «—», контрактом v1 не заполняются; их
  судьба решается задачей рендерера, агентом не заполняются.
