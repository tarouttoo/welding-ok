# Словарь граф ОК (по содержанию, ГОСТ 3.1404-86)

> Заметка для агента. Отображение полей контракта в графы формы — предмет
> **рендерера** (ADR 0001): нормативная таблица —
> [`renderer/README.md`](../renderer/README.md), «Field → графа mapping».
> Этот файл фиксирует только соответствие **по содержанию**, чтобы агент
> понимал, куда попадает каждое поле, и не пытался оформлять документ сам.

## Соответствие «поле контракта → место на форме»

| Поле контракта | Место на форме ОК | Что попадает |
| -------------- | ----------------- | ------------ |
| `product.name` | Шапка «Наименование изделия» и основная надпись | Наименование изделия |
| `product.material` | Основная надпись, графа «материал» | Марка: `ст3`, `09Г2С` |
| `product.process` | Содержание операции | Запись «Способ сварки: …» |
| `operations[i].number` | Основная таблица, графа «Номер операции»; содержание | Номер операции; запись «Операция N» |
| `operations[i].position` | Содержание операции | Запись «Положение сварки: …» |
| `operations[i].transitions[j]` | Содержание операции | Нумерованный список переходов, текст `description` дословно |
| `operations[i].welds[]` | Содержание операции | Запись «Швы: Ш1, Ш2.» |
| `operations[i].sketch_refs[]` | Содержание операции | Запись «Ссылки на эскизы: КЭ1.» (заглушки-ссылки на КЭ) |
| `operations[i].equipment.electrode_type` | Содержание операции | Запись «Электроды: …» — марка электрода, сварочный материал |
| `operations[i].params` | Содержание операции | Запись «Режим: …»: род тока, полярность (только когда задана), ток, диаметр электрода, число проходов |
| `documents[0].assumptions[]` | Содержание операции, блок «Примечания:» | Каждое спорное решение отдельной строкой; остаётся ли блок на выпущенной карте — инженерное решение при приёмке |

## Графы без поля контракта

Следующие графы формы **не заполняются контрактом**: рендерер оставляет их
пустыми, заполняются вручную при приёмке (см.
[`renderer/README.md`](../renderer/README.md)):

- обозначение изделия и обозначение документа;
- код и наименование операции (наименование «Сварка» — по примеру «005
  Сварка» методички ⚠ поле в контракте отсутствует);
- оборудование (станочное) — в контракте только сварочный материал
  `equipment.electrode_type`;
- служебные графы СМ / Проф. / Р / УТ / КР / КОИД / ЕН / ОП / Кшт /
  Т пз / Т шт;
- таблица изменений, подписи.

## Заметки

- Поля `цех`, `участок`, `рабочее место` в контракте v1 отсутствуют ⚠ —
  откуда они берутся (бриф, настройка, приёмка), решается на уровне
  рендерера/контракта, файл знаний это не предрешает.
- Типовой блок режимов РС1 по ГОСТ 3.1407 (методичка, табл. 1: ПС, НП, DC,
  lс, lэ, Пл, U, I, Vс, …) шире v1-контракта: v1 переносит подмножество —
  полярность (`Пл`), ток (`I`); число проходов соответствует `НП` по смыслу
  ⚠. Как оформляется режим на форме — решение рендерера, не файла знаний.
- Форма карты — ГОСТ 3.1118-82 (форма 1/1а); содержание граф —
  ГОСТ 3.1404-86. Эскизы выполняются вручную: в систему входят только
  заглушки-ссылки `КЭ<n>` ([GLOSSARY.md](../GLOSSARY.md)).
